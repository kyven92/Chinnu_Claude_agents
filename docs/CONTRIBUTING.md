# Contributing

## Repo layout

```
ClaudeSetup/
├── bin/claude-setup          # Main CLI entry point (Python)
├── lib/                      # Installer modules (manifest, merge, conflict, backup, prompt, runner)
├── skills/                   # One directory per skill, each with SKILL.md
├── agents/                   # One .md file per agent definition
├── hooks/                    # Bash hook scripts
├── templates/                # CLAUDE.md.template, identity-core.md.template, settings.fragment.json
├── scripts/
│   ├── build-all-skills.sh   # Regenerates ALL_Skills.md from skills/*/SKILL.md
│   └── verify-guide-sync.sh  # Checks skills/ and agents/ are in sync with the HTML guide
├── sources.json              # Upstream source registry (install/update/uninstall commands)
├── install.sh                # Bash bootstrap — version-checks Python, then delegates to bin/claude-setup
├── ALL_Skills.md             # Derived — regenerated by build-all-skills.sh, do not hand-edit
├── claude_code_master_guide.html  # The canonical spec — single-file self-contained HTML
└── tests/                    # Python unit tests (unittest)
```

## Source-of-truth rules

These are locked decisions from the project design:

- **D2**: `claude_code_master_guide.html` is the spec. When skills/agents change, update the guide to match.
- **D3**: `ALL_Skills.md` is derived from `skills/*/SKILL.md` via `build-all-skills.sh` — never hand-edit it.
- **D4**: `sources.json` is the registry for all upstream integrations. New external tools go here first.

## HTML guide sha256

The guide must remain byte-identical across releases unless intentionally updated.

```
sha256: 6c19ec522b790b085cf77904b05b1270c5a4312d637ac9dec5312e2a075e12eb
```

Verify before tagging a release:

```bash
sha256sum claude_code_master_guide.html
```

## Test commands

Run all three before opening a PR:

```bash
# Unit tests
python3 -m unittest discover tests/

# Drift check — skills/ and agents/ must match the HTML guide
bash scripts/verify-guide-sync.sh

# Shell syntax check (if shellcheck is available)
shellcheck hooks/*.sh scripts/*.sh install.sh
```

A dry-run install into a temp directory is also useful for smoke-testing:

```bash
./install.sh --dry-run --target /tmp/test-install
```

## PR checklist

- [ ] `python3 -m unittest discover tests/` passes
- [ ] `bash scripts/verify-guide-sync.sh` exits 0
- [ ] `shellcheck` passes on all `.sh` files (or shellcheck is not available and you've manually reviewed)
- [ ] `ALL_Skills.md` regenerated if skills changed (`bash scripts/build-all-skills.sh`)
- [ ] HTML guide sha256 unchanged (or change is intentional and documented)
- [ ] No hardcoded secrets, paths, or usernames in new code
- [ ] New skills documented in both `overview` and `skills-ref` sections of the HTML guide

## Adding a skill or agent

- **Skill**: follow [ADDING-A-SKILL.md](ADDING-A-SKILL.md).
- **Agent**: create `agents/<name>.md`, add it to the agents table in `claude_code_master_guide.html`, then re-run `verify-guide-sync.sh`.

## Adding an upstream source

Add an entry to `sources.json` with `id`, `tier`, `kind`, `install_cmd`, `verify_cmd`, `update_cmd`, and `uninstall_cmd` fields. See existing entries as examples. Test with:

```bash
./bin/claude-setup install --dry-run
```

Confirm the source appears in the dry-run output under "Sources to install".
